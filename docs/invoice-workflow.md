# Draft invoices and field resending

New ordinary and repeat customer orders save a linked invoice and item snapshot in the same database batch. Sample orders do not create invoices. Already-paid orders retain paid invoice status; checkout payment webhooks settle their linked invoice. No invoice email is sent on order creation. Field and rep-assisted creation also save first and require an explicit send after review.

Admin/staff invoice pages provide an editable recipient and manual Send / Resend action. Delivery failures preserve the saved invoice and do not mark it sent. Successful sends record the selected address in audit history. Resending retains the invoice ID and number and never edits the account email. Emails include the existing secure public invoice/PDF/payment link, allowing a different recipient to review without a customer login. Paid invoices remain paid on resend; paid/processing linked orders cannot start a second invoice charge.

Field order history links admin/staff to invoice review, PDF download and sending. The saved field-document screen also links to the invoice/PDF and supports an explicit resend to the same or a different email. The field invoice review links to existing payment recording. Missing invoices on older active non-sample orders can be created manually through Create Invoice; there is no bulk backfill or historical customer send in this release.

Validation: nine isolated invoice/order/payment tests, 22 existing field workflow tests (including additional same/different-recipient resend assertions), four account-note tests, focused ESLint, TypeScript and production build. Synthetic Chromium at 390px and 1280px verifies save-without-send, explicit email, retained inputs, repeated taps and existing field workflows. No real emails, invoices, payments or inventory changes were created for testing. Physical iPhone Safari and authenticated production sending remain untested. No schema migration or new dependency is required.
